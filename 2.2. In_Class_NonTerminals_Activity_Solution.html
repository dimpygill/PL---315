Solution: Identify Non-Terminals

CSBS 315 · Formal Grammars · C, C#, and Python
Purpose: Practice identifying non-terminals—grammar categories that describe program structure. Unlike terminals, non-terminals are not literal source-code tokens. They are names such as <statement>, <declaration>, and <expression>.

Before You Begin

ConceptMeaningExample
TerminalAn actual token/token kind at the leaves of the grammar.int, =, 20, ;, NEWLINE
Non-terminalAn abstract grammar category used to describe a language construct.<declaration>, <statement>, <expression>

Quick Example

int age = 20;

A simplified grammar can describe this source statement as:

<declaration> ::= int <identifier> = <number> ;

Here, <declaration>, <identifier>, and <number> are non-terminals. The concrete source is ultimately built from terminals/tokens such as int, an identifier token with lexeme age, =, a numeric literal 20, and ;.

Important: The grammars in this activity are intentionally simplified teaching grammars. They are designed to help you recognize grammatical structure; they are not the complete official grammars of C, C#, or Python.

Solution D — Challenge

<program>
    ↓
<statement-list>
    ├── <statement>
    │      ↓
    │   <assignment>
    │      ├── <identifier> → age
    │      ├── =             ← terminal/operator
    │      └── <number>     → 20
    │
    └── <statement>
           ↓
        <function-call>
           ├── <identifier> → print
           ├── (             ← terminal/punctuation
           ├── <identifier> → age
           └── )             ← terminal/punctuation
Why <statement-list>? The program contains two statements: age = 20 and print(age). Together they form the <statement-list>. If a block had only one statement, the statement list could still contain that one statement in this simplified teaching grammar.

Terminal reminder: =, (, and ) are terminals. Python's logical NEWLINE tokens are also terminals; they are not expanded in this diagram because the challenge is focused on identifying non-terminal hierarchy.
Final answer: A terminal is an actual token/token kind that occurs at the leaves of the grammar, such as =, ;, or Python's NEWLINE. A non-terminal is an abstract grammatical category used to describe structure, such as <assignment> or <statement>. Non-terminals are expanded by production rules until the structure ultimately reaches terminals.
