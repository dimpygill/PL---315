Programming Language Paradigms: C, C#, Python, and SQL

Learning goal: explain procedural, object-oriented, multi-paradigm, and declarative styles with small, comparable examples.

1. What Is a Programming Paradigm?

A programming paradigm is a style of organizing instructions. A language can support more than one paradigm. We will compare how we express a task, not claim that each language supports only one style.

Example task: Find a student whose ID is 104. A procedural solution might say “check each ID, one by one.” A declarative solution says “return the row whose ID is 104.”

TermMeaning
ProceduralWrite the sequence of steps.
Object-orientedOrganize related data and behavior into objects.
FunctionalExpress transformations using functions.
DeclarativeDescribe the desired result rather than the full algorithm.
Important: “procedural” and “object-oriented” describe programming styles, not mutually exclusive language categories.

2. C — Primarily Procedural Programming

Procedural programming organizes a solution as a sequence of instructions, often grouped into functions. The programmer explicitly specifies the steps.

C example 1 — Calculate a total

#include <stdio.h>
int main(void) {
    int a = 10, b = 20;
    int total = a + b;
    printf("Total: %d\n", total);
    return 0;
}
// Output: Total: 30

Steps: Declare values → add them → print the result. The order is explicit.

C example 2 — Linear search with a loop

#include <stdio.h>
int main(void) {
    int ids[] = {101, 102, 103, 104, 105};
    int target = 104;
    int found = 0;
    for (int i = 0; i < 5; i++) {
        if (ids[i] == target) {
            found = 1;
            break;
        }
    }
    printf("%s\n", found ? "Found" : "Not found");
    return 0;
}
// Output: Found

Steps: Start at index 0 → compare → advance → stop when found. The for loop explicitly controls the search.

3. C# — Object-Oriented and Multi-Paradigm

C# supports object-oriented programming (classes and objects), but it also supports procedural, functional, and declarative-style features such as LINQ.

C# example 1 — Class and object

using System;
class Student {
    public string Name = "";
    public void SayHello() {
        Console.WriteLine("Hello, " + Name);
    }
}
class Program {
    static void Main() {
        Student s = new Student();
        s.Name = "Asha";
        s.SayHello();
    }
}
// Output: Hello, Asha

Object-oriented idea: The Student object stores Name and provides SayHello(). A class is a blueprint; an object is an instance.

C# example 2 — Procedural-style loop is also possible

using System;
int[] ids = {101, 102, 103, 104, 105};
foreach (int id in ids) {
    if (id == 104) {
        Console.WriteLine("Found");
        break;
    }
}
// Output: Found

C# can express the same explicit search steps without creating a custom class.

C# example 3 — LINQ expresses the result more directly

using System;
using System.Linq;
int[] ids = {101, 102, 103, 104, 105};
bool found = ids.Contains(104);
Console.WriteLine(found);
// Output: True

Contains hides the iteration inside a library method. This is a higher-level expression, but it does not mean C# automatically uses a database index.

4. Python — Multi-Paradigm

Python supports procedural, object-oriented, and functional styles. Python is not exclusively object-oriented.

Python example 1 — Procedural style

a = 10
b = 20
total = a + b
print("Total:", total)
# Output: Total: 30

Python example 2 — Explicit linear search

ids = [101, 102, 103, 104, 105]
for student_id in ids:
    if student_id == 104:
        print("Found")
        break
# Output: Found

Python example 3 — Object-oriented style

class Student:
    def __init__(self, name):
        self.name = name

    def say_hello(self):
        print("Hello,", self.name)

s = Student("Asha")
s.say_hello()
# Output: Hello, Asha

Python example 4 — Concise membership test

ids = [101, 102, 103, 104, 105]
print(104 in ids)
# Output: True

in makes the code shorter; for a Python list, membership testing still normally checks elements sequentially. The programming language supports several styles.

5. SQL — Declarative Query Language

SQL describes WHAT result is wanted. SQL Server decides HOW to retrieve it using a physical execution plan. SQL is declarative, though SQL Server also provides procedural extensions such as T-SQL control flow.

SQL Server example 1 — Return every student

SELECT StudentID, Name
FROM Students;

SELECT: columns wanted. FROM: source table.

SQL Server example 2 — Filter for one student

SELECT Name
FROM Students
WHERE StudentID = 104;

WHERE: the condition rows must satisfy. There is no explicit loop in the query.

SQL Server example 3 — Filter by score

SELECT Name, Score
FROM Students
WHERE Score >= 80;

SQL Server decides whether to scan rows or use an index. SQL has a logical processing model; the physical execution order can differ from the written clause order.

6. Same Task in All Four Languages

Find student ID 104 in a small collection. In C, C#, and Python we can explicitly iterate. In SQL, we specify a predicate and let the database choose a plan.

Use the same data everywhere: 101, 102, 103, 104, 105. Target: 104.

Press Next comparison to simulate a linear search.

C — Explicit loop

for (int i = 0; i < 5; i++) {
    if (ids[i] == 104) { /* found */ break; }
}

Python — Explicit loop

for student_id in ids:
    if student_id == 104:
        break

C# — Explicit loop

foreach (int id in ids) {
    if (id == 104) break;
}

SQL Server — Desired result

SELECT Name FROM Students WHERE StudentID = 104;
The visualization models the explicit loops, not the guaranteed behavior of SQL Server. SQL Server may use a scan, an index seek, or another access path.

7. SQL Indexes and Optimization Connection

A query such as SELECT Name FROM Students WHERE StudentID = 104; expresses a logical request. SQL Server may choose a scan or an index seek based on indexes, estimated row counts, and costs. An index is not always faster, especially for tiny tables or queries returning many rows.

Physical accessSimple meaningWhen it can be useful
Table/clustered index scanRead many or all rows and evaluate conditions.Small tables; large portions of a table needed.
Index seekUse an index to navigate to matching key range(s).Selective predicates and suitable indexes.

Create table and test in SQL Server

CREATE TABLE Students (
    StudentID INT PRIMARY KEY,
    Name VARCHAR(30),
    Score INT
);
INSERT INTO Students (StudentID, Name, Score) VALUES
(101, 'Asha', 90),
(102, 'Ben', 72),
(103, 'Cara', 85),
(104, 'Dev', 88),
(105, 'Eli', 65);

SELECT Name FROM Students WHERE StudentID = 104;

Note: In SQL Server, a primary key commonly creates an index automatically. With five rows, the optimizer may still choose a scan. To inspect the real plan in SQL Server Management Studio, enable Include Actual Execution Plan (Ctrl+M), run the SELECT, and inspect the plan. Do not promise that a seek will appear.

Logical request: “Return the name for ID 104.” Physical plan: SQL Server's chosen operators to produce that result.

8. Guided Comparison and Check Your Understanding

Use the questions and revealed answers to discuss what the programmer controls and what the runtime or database engine controls.

Question 1: Is Python only object-oriented?

No. Python supports procedural, object-oriented, and functional programming. A simple loop is procedural-style Python.

Question 2: Does C# require a class for every search?

No. C# can use a foreach loop or a higher-level method such as Contains. C# is multi-paradigm.

Question 3: What is the key distinction between a loop and SQL WHERE?

The loop explicitly describes iteration; SQL WHERE states a filtering condition and leaves the physical access method to the optimizer.

Question 5: Is SQL always declarative?

SQL queries are predominantly declarative. SQL Server's T-SQL also includes procedural constructs such as IF and WHILE.
