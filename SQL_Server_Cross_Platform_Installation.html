Installing Microsoft SQL Server and Database Tools

Complete cross-platform tutorial: Windows · Ubuntu Linux · macOS (Intel and Apple Silicon)

Learn which components can run on each operating system, install the database engine, connect with a SQL editor, and verify everything with working SQL.

1. Understand what you are installing

SQL Server is the database engine that stores and processes data. SQL Server Management Studio (SSMS) is a graphical client that connects to SQL Server; installing SSMS alone does not install the database engine. Visual Studio Code + MSSQL extension is a cross-platform alternative to SSMS for writing queries and exploring databases.

PlatformSQL Server engineSSMSRecommended SQL client
Windows x64Local installationYesSSMS
Linux x86-64 (supported distro)Local installationNo native versionVS Code + MSSQL extension or sqlcmd
Intel MacIn an x64 Linux VM, or remoteNo native versionVS Code + MSSQL extension
Apple Silicon Mac (M-series)Use a remote x64 server / Azure SQL DatabaseNo native versionVS Code + MSSQL extension

Compatibility: Microsoft SQL Server on Linux requires x86-64. A standard ARM Linux VM on Apple Silicon does not solve this. Running SQL Server via ARM-to-x64 emulation is not a supported installation route. SSMS is a Windows-only application; a Windows VM is an optional way to use SSMS on a Mac, but not required to learn T-SQL.

Cost: SQL Server Developer editions are free for development/testing/education, not production use. SSMS and VS Code are free. Cloud virtual machines may incur charges. Check your license and the current free-offer terms.

Before beginning

  1. Have administrator rights and a stable internet connection.
  2. Allow several gigabytes of free disk space (more for a VM).
  3. Choose a strong password for SQL authentication if needed. Do not reuse a personal password.
  4. Choose the section matching your operating system; do not follow all three installation paths.

2. Windows: install SQL Server + SSMS

Recommended for: Windows 11 x64 with sufficient memory and disk space. Check Microsoft's current system requirements for your edition and Windows build.

Step 1 — Download SQL Server

  1. Open Microsoft's official SQL Server downloads page.
  2. Find Developer (free for nonproduction use) or Express (free, with resource limitations).
  3. Download the installer and run it as administrator.
  4. For a simple first installation, choose Basic if available. For control over instance names and authentication, choose Custom and follow the SQL Server Installation Center wizard.
  5. For Custom installation, select New SQL Server stand-alone installation, accept the license, and include Database Engine Services.
  6. On Instance Configuration, note whether you chose a default instance or named instance (such as SQLEXPRESS).
  7. On Database Engine Configuration, choose Windows authentication and click Add Current User. Mixed Mode is optional for classroom work; if chosen, set a strong sa password.
  8. Finish setup and save the instance name shown by the installer.

Depending on the SQL Server version, installer screens and edition names may differ. For the current installation wizard see Microsoft's Windows setup guide.

Step 2 — Install SSMS separately

  1. Open Microsoft's SSMS installation page.
  2. Download the latest supported SSMS installer, run it, and follow the prompts.
  3. Launch SQL Server Management Studio from Start.

Step 3 — Connect

Connection fieldTypical value
Server typeDatabase Engine
Server name (default instance)localhost or .
Server name (named instance)localhost\SQLEXPRESS (if that is your actual instance name)
AuthenticationWindows Authentication (recommended for a local student machine)
EncryptionUse the secure defaults; for local development, a trusted certificate or explicit local-only trust configuration may be needed

Click Connect. If the server is not found, open Services and confirm SQL Server (MSSQLSERVER) or SQL Server (SQLEXPRESS) is running. You can also check the instance name in SQL Server Configuration Manager.

Step 4 — Test

Click New Query, run SELECT @@VERSION;, and continue to the common exercise in Section 6.

3. Linux (Ubuntu x86-64): install SQL Server + VS Code

This path uses Ubuntu 24.04 x86-64 with SQL Server 2025 CU1 or later. If you have Ubuntu 22.04 or want SQL Server 2022, follow the version-specific Microsoft Ubuntu guide instead of mixing repository versions.

Step 1 — Check your Linux version and architecture

lsb_release -a
uname -m

For this path, Ubuntu should report 24.04 and architecture should report x86_64. If you see aarch64 or arm64, do not attempt this native SQL Server installation.

Step 2 — Install prerequisite utilities

sudo apt-get update
sudo apt-get install -y curl gnupg ca-certificates

Step 3 — Add Microsoft's package signing key

curl -fsSL https://packages.microsoft.com/keys/microsoft.asc \
  | sudo gpg --batch --yes --dearmor -o /usr/share/keyrings/microsoft-prod.gpg

Step 4 — Register the SQL Server 2025 repository

curl -fsSL https://packages.microsoft.com/config/ubuntu/24.04/mssql-server-2025.list \
  | sudo tee /etc/apt/sources.list.d/mssql-server-2025.list

Step 5 — Install the SQL Server engine

sudo apt-get update
sudo apt-get install -y mssql-server

Step 6 — Configure SQL Server

sudo /opt/mssql/bin/mssql-conf setup

Follow the interactive prompts. Choose the appropriate free Developer edition for nonproduction use, accept the license, and create a strong sa password. The precise edition labels can vary by release.

Step 7 — Verify the service

sudo systemctl status mssql-server --no-pager

Look for active (running). If needed:

sudo systemctl start mssql-server
sudo systemctl enable mssql-server

Step 8 — Install command-line SQL tools (optional but useful)

curl -fsSL https://packages.microsoft.com/config/ubuntu/24.04/prod.list \
  | sudo tee /etc/apt/sources.list.d/mssql-release.list
sudo apt-get update
sudo apt-get install -y mssql-tools18 unixodbc-dev

Accept Microsoft's license prompt if shown. Test a local connection (enter your password when prompted):

/opt/mssql-tools18/bin/sqlcmd -S localhost -U sa -C

At the 1> prompt, enter:

SELECT @@VERSION;
GO

Enter QUIT to exit. The -C option trusts the server certificate; it is shown here for a local development connection only. For remote connections, configure a valid trusted certificate.

Step 9 — Install a graphical SQL editor

  1. Install Visual Studio Code for Linux.
  2. Open Extensions (Ctrl+Shift+X), search SQL Server (mssql) published by Microsoft, and install it.
  3. Open the extension's connection panel, create a new connection, and enter server localhost, SQL login sa, and your password.
  4. Use the extension's connection security options appropriately. If you encounter a self-signed certificate error on a local-only practice instance, explicitly trust the local server certificate for development; do not disable verification for public servers.
  5. Create a .sql file, select your connection, and run SELECT @@VERSION;.

SSMS is not available natively on Linux. If you require SSMS specifically, install it on a separate Windows computer or Windows VM and connect to the Linux SQL Server remotely.

Optional — Connect remotely

SQL Server typically listens on TCP port 1433. Do not expose it to the public internet. Prefer a VPN or SSH tunnel. If a direct connection is necessary on a trusted network, restrict firewall access to the specific client IP and configure TLS. Never open port 1433 to everyone.

4. macOS: Intel vs. Apple Silicon

Step 1 — Identify your processor

  1. Click the Apple menu → About This Mac.
  2. Look for Chip (Apple M-series) or Processor (Intel).

Path A — Intel Mac: Ubuntu x64 virtual machine

  1. Download a macOS-compatible virtual machine application such as VirtualBox or UTM; check that the version supports your Intel Mac and macOS release.
  2. Download the Ubuntu 24.04 x64/amd64 ISO from Ubuntu.
  3. Create a new VM, choose Linux/Ubuntu 64-bit, attach the Ubuntu ISO, and allocate approximately 4 GB RAM, 2 CPU cores and 30–40 GB storage if your Mac has sufficient resources. These are classroom planning values, not a substitute for Microsoft's minimum requirements.
  4. Install Ubuntu, log in, and confirm uname -m returns x86_64.
  5. Follow Section 3 inside the Ubuntu VM to install SQL Server.
  6. On macOS itself, download VS Code for macOS and install Microsoft's SQL Server (mssql) extension.
  7. Connect from macOS to the VM using its reachable IP address and SQL Server port 1433, with network access restricted to the Mac. Depending on the VM software, configure host-only/bridged networking or a NAT port-forward; consult that VM application's documentation.

VM networking tip: localhost on macOS refers to the Mac, not automatically to the Linux guest. Use the guest's reachable address, or a deliberately configured localhost port forward.

Path B — Apple Silicon Mac (M1/M2/M3/M4/M5): remote SQL Server

A standard Ubuntu VM on Apple Silicon uses ARM64, whereas SQL Server for Linux requires x86-64. For a reliable supported course setup, use a remotely hosted x64 SQL Server or Azure SQL Database instead of trying to install the SQL Server engine locally through CPU emulation.

  1. Open Azure's free-services page and review Azure SQL Database free-offer eligibility, limits and billing safeguards.
  2. Sign in to the Azure portal with an eligible account/subscription.
  3. Create an Azure SQL Database, making sure any free-offer eligibility is applied and the behavior at the free limit avoids unintended charges.
  4. Record the server name (typically your-server.database.windows.net), database name and SQL login. Allow only your current client IP through the Azure SQL firewall as needed.
  5. Install VS Code for macOS and Microsoft's SQL Server (mssql) extension.
  6. Create a new SQL connection using the full server hostname, your database name and appropriate authentication. Keep encryption enabled and validate the server certificate.
  7. Open a query and run SELECT @@VERSION;, followed by the common SQL exercise.

Azure SQL Database vs SQL Server: Azure SQL Database supports T-SQL learning but is a managed database service, not a full Linux/Windows SQL Server VM. Some server-level administrative features differ. A full x64 SQL Server VM in Azure is another option but incurs VM charges.

What if a Mac user absolutely needs SSMS?

SSMS is Windows-only. Run SSMS on a supported Windows machine or Windows VM and connect to SQL Server. On Apple Silicon, a Windows 11 ARM VM may run supported SSMS builds, but SQL Server's local engine compatibility is a separate issue. For ordinary SQL coursework, VS Code is simpler.

5. Free online option for Windows, macOS, and Linux: Azure SQL Database

No SQL Server installation, SSMS installation, or VM is required. Azure SQL Database is a Microsoft-hosted SQL database service. Students can use the Azure portal's browser-based Query editor to execute T-SQL on any operating system. It is a managed service, not a full SQL Server installation.

Free offer: Eligible subscriptions can create up to 10 free Azure SQL databases, each with a monthly allowance of 100,000 vCore-seconds of compute, 32 GB data storage, and 32 GB backup storage (subject to current offer terms). The free allowance renews monthly; availability and eligibility vary by subscription. The query editor does not require a separate paid license, but the database and other Azure resources can incur charges if configured outside the offer.

Step 1 — Register for Azure

  1. Visit Azure for Students if eligible, or review Azure free services.
  2. Sign in with a Microsoft account and follow the prompts to establish an eligible Azure subscription. Student verification may be required. Not all account types qualify; Azure for Students Starter is not the same as the full Azure for Students offer.
  3. Open Azure portal.

Step 2 — Create a database using the free offer

  1. Go to Azure SQL Hub or search for SQL databases in the portal.
  2. Choose the option to create a SQL database and select Start free when offered. Check for the confirmation Free offer applied! before proceeding.
  3. Select your subscription and resource group; name the database SQLPracticeDB.
  4. Create or select a logical SQL server; choose a region and set a strong administrator password. Store credentials securely.
  5. For Behavior when free limit reached, choose Auto-pause the database until next month, not a paid continuation option.
  6. Review every tab and confirm that the free offer applies and the estimated database charge is $0. Other selected Azure services may still cost money. Select Review + create, then Create.
Cost safeguard: Do not assume that every Azure resource is free. Verify the free-offer indicator and pricing before deployment, avoid extra paid resources, and review Cost Management periodically. A free student credit is different from the renewable Azure SQL Database free offer.

Step 3 — Open the browser-based SQL Query editor

  1. In Azure portal, open SQL databases and select SQLPracticeDB.
  2. Choose Query editor (preview) from the database menu (its location may vary with portal updates).
  3. Sign in with the database's SQL administrator credentials or supported Microsoft Entra authentication.
  4. If the portal reports that your IP address is blocked, add only your current client IP to the SQL server firewall rules using the portal's prompt or Networking settings. Avoid opening access to all IP addresses.
  5. Enter SELECT @@VERSION AS ServerVersion; and click Run. Results should appear beneath the editor.

Step 4 — Practice T-SQL without installing software

Run this example in the Azure Query editor:

CREATE TABLE CourseStudents (
    StudentID INT PRIMARY KEY,
    StudentName VARCHAR(100) NOT NULL,
    GPA DECIMAL(3,2)
);

INSERT INTO CourseStudents VALUES
(1, 'Asha', 3.80),
(2, 'Sam', 3.95);

SELECT StudentName, GPA
FROM CourseStudents
WHERE GPA > 3.5
ORDER BY GPA DESC;

Expected result: Sam (3.95), followed by Asha (3.80). To repeat the exercise, first run DROP TABLE CourseStudents; in your own practice database.

Optional — Connect using VS Code instead

  1. Install Visual Studio Code on Windows, Linux, or macOS.
  2. Install Microsoft's SQL Server (mssql) extension.
  3. In the Azure database's Overview page, copy its fully qualified server name (for example, example.database.windows.net).
  4. Create a connection using that server name, database SQLPracticeDB, your configured authentication, and encryption enabled.
  5. Run the same SQL statements in a .sql file.

Which setup should students choose?

Learning goalRecommended setup
Learn T-SQL, tables, joins, views, stored procedures and transactionsFree Azure SQL Database + browser Query editor (if eligible)
Use a full local SQL Server database engine on WindowsSQL Server Developer Edition + SSMS
Practice Linux installation and SQL Server service administrationSupported x64 Linux installation or VM
Practice from Intel or Apple Silicon Mac without VM complexityAzure SQL Database + Query editor or VS Code

Limitations: The browser Query editor is useful for learning, but is not a complete replacement for SSMS. Some advanced administration features, large result sets, and server-level commands are unavailable or different in Azure SQL Database. For course work involving SQL Server administration, use a full server instance.

6. Common installation verification exercise

After connecting to your SQL Server instance or Azure SQL Database, open a query window. First, verify connectivity:

SELECT @@VERSION AS ServerVersion;
SELECT DB_NAME() AS CurrentDatabase;

Next, create a practice database. For local SQL Server (with permission to create databases), run:

CREATE DATABASE CollegePractice;
GO
USE CollegePractice;
GO

For Azure SQL Database: Create a database in the Azure portal first and connect directly to that database; skip CREATE DATABASE and USE in the query window.

Run this script in the practice database:

CREATE TABLE Students (
    StudentID INT PRIMARY KEY,
    FullName NVARCHAR(100) NOT NULL,
    GPA DECIMAL(3,2) NULL
);

INSERT INTO Students (StudentID, FullName, GPA)
VALUES (1, 'Asha Patel', 3.80),
       (2, 'Jordan Lee', 3.50),
       (3, 'Sam Rivera', 3.95);

SELECT StudentID, FullName, GPA
FROM Students
WHERE GPA >= 3.70
ORDER BY GPA DESC;

Expected: Two rows, Sam Rivera (3.95) and Asha Patel (3.80), in that order. If these appear, your database connection and basic T-SQL execution work.

Optional clean-up:

DROP TABLE Students;

Do not run clean-up commands on shared or production databases.

7. Troubleshooting

SSMS cannot find the SQL Server instance (Windows)

Confirm the SQL Server service is running, check the exact default/named instance in SQL Server Configuration Manager, and try localhost or localhost\SQLEXPRESS as appropriate. SSMS itself does not install the database engine.

Login failed for user 'sa'

Verify the SQL authentication mode, correct password and enabled account. On a local Windows installation, Windows Authentication is usually simpler. Avoid enabling sa when not needed.

SSL / certificate trust error

Use a trusted TLS certificate for real remote connections. For an isolated local development environment only, the client may provide a trust-server-certificate setting; do not use this to bypass certificate validation on internet-facing servers.

Linux package 'mssql-server' cannot be found

Check lsb_release -a and uname -m, confirm the repository matches both Ubuntu and SQL Server versions, and rerun sudo apt-get update. ARM64 is not a supported native engine target.

Linux SQL Server service fails to start

Check sudo systemctl status mssql-server and sudo journalctl -u mssql-server -n 80 --no-pager. Verify memory, disk space, OS support, and the setup password requirements.

Mac VS Code cannot connect to Ubuntu VM

Check whether the VM has a reachable IP or a configured NAT port-forward. Confirm SQL Server is running and that network/firewall rules allow traffic only from the intended host. localhost on the Mac is not automatically the VM.

Azure SQL Database connection times out

Verify the complete server hostname, selected database, Azure SQL firewall allowlist for the client IP, internet access, and TLS settings. Confirm the database is online and that you are not trying to connect to an auto-paused or otherwise unavailable resource.
