Programming Language Design • Practical Assignment

Same Problem, Three Entry-Point Designs

Build one program in C, C#, and Python using VS Code. Investigate how each language determines where execution begins.

1. Purpose and Learning Outcomes

Central design question: When you run a program, how does its language and runtime determine where execution begins?

You will create three separate projects—one per language—that solve the same simple problem. Keeping the computation the same lets you focus on the differences in program structure, compilation, and launching.

After completing this assignment, you should be able to:

  • Identify the entry mechanism used by your C, C#, and Python programs.
  • Distinguish a source filename from a function or compiler-generated entry point.
  • Explain what happens when source files are renamed.
  • Explain why the Python file selected in the launch command matters.
  • Support your comparison with terminal output from your own experiments.

Terms used in this assignment

  • Entry point: the designated starting mechanism for execution of the application code. Runtime startup can occur before your code begins.
  • Top-level statements: statements written outside an explicitly declared function or method in the source code.
  • Compile: translate source code into another form before execution.
  • Executable: a built program that can be launched.
  • Module: a Python unit of code, commonly a .py file. The module launched as the main program has the special name __main__.

2. The Shared Problem: Student Grade Calculator

  1. Ask for a student name. A single first name is sufficient.
  2. Ask for three scores. Scores may contain decimal values.
  3. Calculate the average: (score1 + score2 + score3) / 3.
  4. Display the name and average, with the average formatted to two decimal places.
  5. Display Pass when the average is at least 70; otherwise display Fail.

Enter score 1: 80

Status: Pass

3. Prepare Your VS Code Workspace

  1. Create a parent folder named EntryPoint_Assignment.
  2. Inside it, create EntryPoint_C, EntryPoint_CSharp, and EntryPoint_Python.
  3. Open the parent folder in VS Code.
  4. Select Terminal → New Terminal. Run each command from its corresponding project folder.
  5. Confirm that GCC, the .NET SDK, and Python are available using gcc --version, dotnet --version, and python --version.

The commands below use Windows PowerShell, matching the VS Code terminal workflow. If your Python installation uses py or python3, use that command consistently and record it.

A C or Python project here is an organized source folder. The C# console project additionally contains a .csproj file that defines the .NET project.

4. Part A — C: An Explicit Entry Function

  1. Open a terminal in EntryPoint_C.
  2. Create start.c. Implement the calculator using int main(void). Put the required executable statements inside main and end with return 0;.
  3. Compile and run:
gcc start.c -o gradeapp.exe
.\gradeapp.exe
  1. Run all four test cases and record the results.
  2. Predict what will happen if you rename the source file. Write your prediction before continuing.
  3. Rename start.c to begin.c in VS Code. Keep the function named main.
  4. Recompile using the new filename, then run:
gcc begin.c -o gradeapp.exe
.\gradeapp.exe
  1. Save the successful compile command and output from the renamed-file run as evidence.
After renaming, compile successfully before running. Running an old executable alone does not prove that the renamed source builds. On macOS/Linux, use gcc begin.c -o gradeapp and then ./gradeapp.

Record your observations

  • Did renaming the file change the behavior?
  • Which identifies the designated entry function: begin.c or main?
  • What did you change in the build command, and why?

5. Part B — C#: Top-Level Statements

  1. Open a terminal in the existing, empty EntryPoint_CSharp folder.
  2. Create the console project:
dotnet new console
  1. Open the generated Program.cs. Replace its sample program with your grade calculator.
  2. Use top-level statements. Do not declare a class or an explicit Main method for this part.
  3. Run the project from the folder containing its .csproj file:
dotnet run
  1. Run all four test cases and record the results.
  2. Predict what will happen if you rename Program.cs.
  3. Rename Program.cs to GradeCalculator.cs. Do not copy it or leave a second file containing top-level statements.
  4. Run dotnet run again from the same project folder.
  5. Save the command and successful output as evidence.

C# syntax reference

These small examples are syntax hints; adapt them to implement the calculator.

TaskExample
Access console types explicitlyusing System; at the beginning of the file
Display a prompt without a new lineConsole.Write("Enter name: ");
Read a namestring name = Console.ReadLine() ?? "";
Read a decimal numberdouble score = double.Parse(Console.ReadLine() ?? "0");

Choose between two actionsif (condition) { ... } else { ... }
  • double stores floating-point numbers; double.Parse converts numeric text to a number.
  • ?? supplies a fallback when a value is null. It does not validate malformed input.
  • The $ prefix allows expressions inside { } in a string. F2 formats a number with two decimal places.
  • C# statements commonly end with ;. Braces { } group statements.
Only one source file in this C# project may contain top-level statements. Run dotnet run for the project rather than passing a source filename to this command.

Record your observations

  • Did the renamed file still run as part of the project?
  • Did your source code explicitly contain Main?
  • What does the compiler generate for top-level statements? Does it literally insert that code into your source file?

6. Part C — Python: Choose the Launched Module

  1. Open a terminal in EntryPoint_Python.
  2. Create start.py and implement the grade calculator using top-level statements. Do not define a main() function for this experiment.
  3. Add print("Module name:", __name__) at the beginning so you can observe the module's execution name.
  4. Run the script:
python start.py
  1. Run all four calculator test cases and record the results.
  2. Predict what will happen if you rename the script and update the launch command.
  3. Rename start.py to begin.py and run:
python begin.py
  1. Create a separate file, another.py, containing:
print("another.py is running")
print("Module name:", __name__)
  1. Predict what will execute when you run the following command, then test it:
python another.py
  1. Save output from both begin.py and another.py.

Record your observations

  • Which file executed after each launch command?
  • What value did __name__ display in each directly launched script?
  • Did launching another.py automatically run the calculator in begin.py?
  • Is a function named main required for either script?
