1. What is a Hash Table? (Real-World Analogy)

The Mailbox / Gym Locker System

Imagine a post office with 10 numbered mailboxes (0 through 9). Instead of searching every mailbox one by one to find your package, a smart machine takes your Name and instantly tells you: "Your package belongs in Box #4!"

That's exactly what a Hash Table does:

  • Key The label you look up with (e.g., student name "Alice", username, or word).
  • Value The actual data stored (e.g., phone number 555-0199 or score 95).
  • Hash Function The formula machine that calculates which box number (index) to place the data in.
Why is it fast? Searching a normal list takes time (O(n)). A hash table jumps directly to the right box in 1 step (O(1) average time)!

2. How Hash Functions Work

Converting text into a valid array index step-by-step.

An array only understands numerical indexes like 0, 1, 2, 3. Since keys can be text like "banana" or "user_99", we use a Hash Function to convert text into numbers.

1

Convert Characters to ASCII

Each character has a hidden number value. E.g., 'C' = 67, 'a' = 97, 't' = 116.

2

Sum/Mix the Numbers

Add or multiply character values together to produce a big total integer (Hash Code).

3

Fit Inside Array Size (%)

Use Modulo operator % Capacity so the number fits within array bounds.

Array Index = ( Hash Code of Key ) % ( Total Table Capacity )

3. What is a Collision & How Do We Fix It?

When two different keys land in the exact same array slot.

1. Separate Chaining (Linked Lists)

Used by C & C#

Instead of holding just 1 item, every slot in the array points to a Linked List (a chain of items). If two items hash to Slot #2, they are simply chained together!

Slot [2]: "Cat": 5 ➜ "Dog": 8
Pros: Easy to grow, handles many collisions.
Cons: Uses extra memory for list pointers.

2. Open Addressing (Linear Probing)

Used by Python

If your assigned slot is already taken by another item, look for the next available empty slot (Slot + 1, Slot + 2, etc.) right in the main array.

Slot [2]: "Cat": 5 (Occupied!)
Slot [3]: "Dog": 8 (Placed in next open slot)
Pros: Great CPU cache efficiency, no linked list pointers.
Cons: Array can get crowded quickly if full.

4. Resizing & Load Factor

What happens when the Hash Table gets full?

Load Factor ($\alpha$) Formula

Measures how "crowded" the hash table is.

Load Factor = ( Number of Elements ) / ( Total Array Capacity )

When the Load Factor exceeds a threshold (typically 0.70 or 70%), search speeds begin to slow down because collisions become frequent.

Trigger Step 1

Table reaches 70% full

Trigger Step 2

Double Capacity (e.g. 4 → 8)

Trigger Step 3

Rehash all old keys into new table

6. Language Implementations (C, Python, C#, SQL)

Compare syntax and underlying mechanics across languages.

C: Low-level manual hash table with Separate Chaining struct nodes. 
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

// Linked List Node for Chaining
typedef struct Node {
    char *key;
    int value;
    struct Node *next;
} Node;

// Hash Table Structure
typedef struct {
    Node **buckets;
    int capacity;
} HashTable;

// Simple Hash Function: Sum of character ASCII codes
int hash(const char *key, int capacity) {
    int sum = 0;
    for (int i = 0; key[i] != '\0'; i++) {
        sum += key[i];
    }
    return sum % capacity; // Fit within capacity
}

// Insert Key-Value Pair
void insert(HashTable *table, const char *key, int value) {
    int index = hash(key, table->capacity);
    Node *newNode = malloc(sizeof(Node));
    newNode->key = strdup(key);
    newNode->value = value;
    newNode->next = table->buckets[index];
    table->buckets[index] = newNode; // Put at head of linked list
}
Python: Built-in dict uses high-performance compact array open addressing. 
# Standard Python Dictionary (Hash Table under the hood)
user_scores = {}

# Insert Key-Value Pairs - O(1)
user_scores["Alice"] = 95
user_scores["Bob"] = 87

# Lookup Value - O(1)
print(user_scores.get("Alice"))  # Output: 95

# Python dict preserves insertion order (Python 3.7+)
for key, value in user_scores.items():
    print(f"{key}: {value}")
C#: Dictionary<TKey, TValue> uses strongly typed parallel arrays. 
using System;
using System.Collections.Generic;

class Program {
    static void Main() {
        // Create strongly typed Hash Table
        Dictionary<string, int> scores = new Dictionary<string, int>();

        // Add elements
        scores["Alice"] = 95;
        scores.Add("Bob", 87);

        // Safe lookup
        if (scores.TryGetValue("Alice", out int score)) {
            Console.WriteLine($"Alice's score: {score}");
        }
    }
}

What is a bucket? Is it a page?
A bucket is a slot in a hash index that references zero or more entries. A page is an 8 KB storage unit used in traditional SQL Server disk-based indexes. A memory-optimized hash index uses buckets in memory rather than traditional 8 KB index pages. When two keys map to the same bucket, SQL Server follows a chain and checks the actual key values.
BUCKET_COUNT = 1048576 requests 1,048,576 hash buckets; it does not create 1,048,576 database pages. Unlike many application-level hash tables, a SQL Server memory-optimized hash index does not automatically resize its bucket array as rows are inserted.

        
SQL Server example: create a memory-optimized hash index
CREATE TABLE dbo.UserScores (
    UserId INT NOT NULL PRIMARY KEY NONCLUSTERED,
    UserName NVARCHAR(50) NOT NULL,
    Score INT NOT NULL,
    INDEX IX_UserName_Hash NONCLUSTERED HASH (UserName)
        WITH (BUCKET_COUNT = 1048576)
) WITH (MEMORY_OPTIMIZED = ON, DURABILITY = SCHEMA_AND_DATA);

SELECT * FROM dbo.UserScores WHERE UserName = 'Cara';
Memory-optimized tables require the appropriate database configuration, including a MEMORY_OPTIMIZED_DATA filegroup for applicable SQL Server deployments. The optimizer determines the actual access path.
