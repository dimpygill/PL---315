1. Introduction: The Two Pillars of Memory

When your program runs, the operating system gives it a chunk of RAM. To manage this space efficiently, runtime environments (like .NET, Java, or Node.js) split memory into two main areas: The Stack and The Heap.

Feature Stack Memory Heap Memory
How it works Last-In, First-Out (LIFO). Like a stack of cafeteria trays. Random access warehouse. Items can be placed anywhere.
Speed Extremely fast (handled directly by CPU pointer). Slower (requires allocation tracking and pointers).
Lifetime Automatically cleaned up when a function finishes. Managed by Garbage Collector (GC) when no pointers remain.
What lives here? Local primitive variables, function parameters, and reference pointers. Objects, arrays, strings, and dynamic collections.

2. Value Types vs. Reference Types

Value Types hold their actual data directly where the variable is declared. If you copy a value type, you get an independent duplicate.

Reference Types store a pointer (address) on the stack pointing to the actual data located on the heap. If you copy a reference variable, you only copy the address—both variables now point to the exact same object!

3. String Handling & The Loop Performance Trap

Strings are reference types stored on the heap, but they have a unique property: Immutability. Once a string object is created on the heap, its contents cannot be changed.

Why is `str += "a"` in a loop poor performance?

If you concatenate characters inside a loop like `for(int i=0; i<1000; i++) { text += "a"; }`, Python, C#, and Java cannot modify the original string in place. Instead:

  1. A brand new, larger string object is allocated on the heap.
  2. All old characters and the new character are copied over.
  3. The old string is abandoned, creating massive garbage collection overhead.

4. How Dynamic Lists & Arrays Work Under the Hood

A list feels dynamic because it can grow infinitely, but memory requires fixed, contiguous blocks. Behind the scenes, a dynamic list consists of:

  • A list metadata object on the heap keeping track of item count.
  • An internal backing array on the heap holding items side-by-side.

What happens when it overflows? When you exceed capacity, the list allocates a brand new array twice the size on the heap, copies all existing items over, and discards the old array.
