#include <stdio.h>
int main() {

Week 02 Syntax, Tokens & Grammars
Both
▼
Topics
  • Lexical analysis — how source code becomes tokens
  • Formal grammars: BNF and EBNF notation
  • Syntax diagrams and parse trees
  • How Python's indentation-based syntax differs from C and C#'s brace-based syntax
  • Abstract Syntax Trees (ASTs) — what the compiler actually sees
Design Contrast
C — braces define scope
if (x > 0) {
    printf("positive");
}
C# — braces, richer syntax
if (x > 0) {
    Console.WriteLine("positive");
}
Python — indentation defines scope
if x > 0:
    print("positive")
Assignment 1 due: Write the BNF grammar for a simple if-statement in all three languages. Note: C and C# share grammar structure — what does that tell us about language lineage?
UNIT 02 Names, Variables & Scope — Weeks 3–4
Week 03 Variables, Binding & Lifetime
Both
▼
Topics
  • Variables as abstractions — name, type, value, address, lifetime
  • Binding times: static vs. dynamic binding
  • Variable lifetime — stack vs. heap allocation
  • C: explicit declaration, fixed type, manual lifetime
  • C#: static typing with optional type inference via var
  • Python: dynamic binding, type inferred at runtime
Design Contrast
C — always explicit
int age = 25;
float gpa = 3.8;
char grade = 'A';
C# — explicit or inferred
int age = 25;       // explicit
var gpa = 3.8;      // inferred
string grade = "A"; // explicit
Python — always inferred
age = 25
gpa = 3.8
grade = 'A'
Discussion: C# offers both explicit and inferred typing via var. Is that the best of both worlds, or does it create ambiguity? Compare with C's strict approach and Python's fully dynamic approach.
Week 04 Scope Rules & Symbol Tables
Both
▼
Topics
  • Static (lexical) vs. dynamic scoping — definitions and tradeoffs
  • Block scope, function scope, file scope in C
  • C# scoping: block, method, class, namespace — four levels
  • LEGB rule in Python (Local, Enclosing, Global, Built-in)
  • Symbol tables — how compilers track names
  • Shadowing — when inner scope hides outer scope across all three languages
Assignment 2 due: Trace the scope of 5 variables through a given program in all three languages. C# introduces namespace and class scope — how does this compare to C's file scope and Python's module scope?
UNIT 03 Type Systems — Weeks 5–6
Week 05 Static vs. Dynamic Typing
Both
▼
Topics
  • Static vs. dynamic typing — when type checking happens
  • Strong vs. weak typing — what operations are permitted
  • C: strongly typed, statically checked, explicit casts
  • C#: strongly typed, statically checked, nullable types with ? operator
  • Python: strongly typed, dynamically checked, duck typing
  • Type coercion and implicit conversions — where bugs hide
Design Contrast
C — compile time, no null safety
int x = "hello"; 
// ❌ Error at compile time
int *p = NULL; // null allowed
C# — compile time + nullable
string s = null;  // warning
string? s2 = null; // safe
int x = "hello";  // ❌ compile
Python — caught at runtime
x = 5
x = x + "hello"
# ❌ TypeError at runtime
Discussion: C# adds nullable reference types to warn about nulls at compile time — a feature C lacks entirely. How does this design choice improve on C while still differing from Python's approach?
Week 06 Primitive Types, Strings & Arrays
Both
▼
Topics
  • Primitive types in C: int, float, char, double — fixed sizes
  • Python's unified object model — everything is an object
  • Strings in C: char arrays, null termination, manual length
  • Strings in C#: immutable string class, rich methods, interpolation
  • Strings in Python: immutable, rich methods, Unicode by default
  • Arrays in C (fixed) vs. C# arrays/List<T> vs. Python lists (dynamic)
C — strings are dangerous
char name[20] = "Dimpy";
// Fixed size, no bounds check
// Overflow = security bug
C# — safe, feature-rich
string name = "Dimpy";
Console.WriteLine(name.ToUpper());
Console.WriteLine($"Hi {name}!");
Python — strings are safe
name = "Dimpy"
print(name.upper())
print(f"Hi {name}!")
Midterm Exam — Week 6: Covers Units 1–3. Mix of grammar writing, scope tracing, and type system analysis questions.
UNIT 04 Control Flow & Functions — Weeks 7–8
Week 07 Control Structures & Error Handling
Both
▼
Topics
  • Conditionals, loops, switch/match — design decisions compared
  • Goto in C — why it exists, why it's avoided
  • Error handling: C's return codes vs. structured exceptions in C# and Python
  • C#: try/catch/finally with typed exceptions and custom exception classes
  • Why languages make different error handling choices
  • Structured exception handling — design tradeoffs
C — return code convention
int result = divide(10, 0);
if (result == -1) {
    printf("Error!");
}
C# — typed exceptions
try {
    int r = 10 / 0;
} catch (DivideByZeroException e) {
    Console.WriteLine(e.Message);
} finally { /* always runs */ }
Python — exceptions
try:
    result = 10 / 0
except ZeroDivisionError:
    print("Error!")
finally:
    pass  # always runs
Discussion: C# and Python both use structured exceptions — yet they're very different languages. Why did both converge on this model? What did they learn from C's return-code approach?
Week 08 Functions & Parameter Passing
Both
▼
Topics
  • Pass by value vs. pass by reference — C pointers vs. Python object references
  • Return values — single return in C vs. multiple returns in Python
  • Recursion and stack frames
  • First-class functions in Python — functions as values
  • C# delegates, Func<T> and lambda expressions
  • Function pointers in C — the low-level equivalent
C — pointer for by-reference
void increment(int *x) {
    *x = *x + 1;
}
int n = 5;
increment(&n); // n is now 6
C# — ref keyword + tuples
void Increment(ref int x) => x++;
int n = 5;
Increment(ref n); // n is now 6

(int min, int max) MinMax(int[] a)
    => (a.Min(), a.Max());
Python — multiple return values
def min_max(nums):
    return min(nums), max(nums)

lo, hi = min_max([3,1,4,1,5])
Assignment 3 due: Implement binary search in all three languages. Compare function signatures, parameter passing, and return values. Note how C# sits between C's explicit pointers and Python's clean syntax.
UNIT 05 Memory Management — Weeks 9–10
Week 09 Manual Memory Management in C
C
▼
Topics
  • Stack vs. heap — where variables live in memory
  • malloc, calloc, realloc, free — the C memory API
  • Memory leaks — what happens when you forget to free
  • Dangling pointers — use after free bugs
  • Buffer overflows — the security consequence of manual memory
C — fully manual
int *arr = malloc(5 * sizeof(int));
arr[2] = 99;
free(arr); // forget = leak
arr = NULL; // best practice
C# — GC + IDisposable
int[] arr = new int[5];
arr[2] = 99;
// GC handles deallocation
// Use 'using' for resources
Python — fully automatic
arr = [0] * 5
arr[2] = 99
# Memory freed automatically
# when arr goes out of scope
Discussion: C# chose GC over manual memory — the same choice Python made. Why do high-level languages converge on this? And what does C still offer that GC languages can't match?
Week 10 Garbage Collection & Memory Models
Python
▼
Topics
  • Garbage collection strategies — reference counting, mark-and-sweep, generational
  • Python's GC: reference counting + cyclic GC
  • C#'s GC: generational (.NET CLR) — more sophisticated than Python's
  • C# IDisposable and using — deterministic cleanup within GC
  • Performance cost of GC — why C is still faster than both
  • When manual memory is worth the risk — embedded systems, game engines, OS kernels
Assignment 4 due: Compare memory models across all three languages. Include: who manages memory, what the GC strategy is (where applicable), what can go wrong, and the performance tradeoff.
UNIT 06 Paradigms & Final Evaluation — Weeks 11–12
Week 11 Paradigm Deep Dive — Procedural vs. OOP vs. Functional
Both
▼
Topics
  • C as the gold standard procedural language — functions, structs, no OOP
  • C# as the OOP-first language — classes, interfaces, inheritance, LINQ
  • Python's multi-paradigm nature — OOP, functional, procedural all supported
  • Functional features: LINQ in C#, map/filter/lambda in Python, function pointers in C
  • Why language designers choose to support multiple paradigms
C — procedural only
struct Dog { char name[50]; };
void bark(struct Dog d) {
    printf("%s: Woof!\n", d.name);
}
// No classes, no inheritance
C# — OOP-first + LINQ
class Dog {
    public string Name { get; set; }
    public void Bark() =>
        Console.WriteLine($"{Name}: Woof!");
}
Python — your choice of paradigm
class Dog:
    def bark(self):
        print(f"{self.name}: Woof!")

# OR functional:
bark = lambda n: print(f"{n}: Woof!")
Final Project begins: Students write a comparative evaluation of all three languages — C, C#, and Python — across every design dimension covered in the course.
