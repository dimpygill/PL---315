1. What is a database? What is a relational database?

A database is an organized collection of data. A college might store students and courses; a store might store products and orders; an HR department might store employees and departments.

A relational database organizes data into tables. Each table contains rows (individual records) and columns (properties of each record). Tables can be connected through matching key values.

DepartmentID 10 means IT. Instead of repeating the text “IT” for every employee, the Employees table stores a reference to the Departments table. This relationship reduces repeated data and helps keep department names consistent.

Vocabulary: Table = collection of records; row = one record; column = one property; schema = the structure of the tables, including their columns, types, and constraints.

2. Microsoft SQL Server, SQL and T-SQL

Microsoft SQL Server

Microsoft SQL Server is a relational database management system (RDBMS): software that stores data, enforces rules, handles access, and runs queries. You send a query to SQL Server; its database engine processes the request and returns a result. SQL Server is the database software, not the programming language.

SQL

SQL means Structured Query Language. It is a largely declarative language: you describe what data you want, not the detailed algorithm for retrieving it.

SELECT FirstName, Salary
FROM Employees
WHERE Salary > 70000;

This asks for employee names and salaries above 70,000. You do not write a loop to inspect every row; SQL Server decides how to execute the query.

T-SQL

T-SQL (Transact-SQL) is Microsoft's extension of SQL, used by SQL Server. It includes standard-style SQL queries plus Microsoft-specific features such as variables, procedural control flow, and TOP.

-- T-SQL: show the two highest-paid employees
SELECT TOP (2) FirstName, Salary
FROM Employees
ORDER BY Salary DESC;

How a query works (simplified): SQL Server parses the text (checks the query's grammar), validates names and types (such as whether Employees exists), optimizes the query (chooses an efficient execution plan), executes that plan (reads the needed data), and returns result rows. You describe the result; the database engine handles the retrieval steps.

3. Three important groups of SQL statements

GroupFull namePurposeTypical statements
DDLData Definition LanguageCreate or change database structureCREATE, ALTER, DROP
DMLData Manipulation LanguageAdd, modify, or remove stored rowsINSERT, UPDATE, DELETE
DQLData Query LanguageRetrieve informationSELECT

For introductory teaching, SELECT is often placed under DQL. Some references classify SELECT within DML instead; these categories are teaching conventions rather than different SQL engines.

DDL example — define a table

CREATE TABLE Departments (
    DepartmentID INT PRIMARY KEY,
    DepartmentName VARCHAR(50) NOT NULL
);

INT means whole number; VARCHAR(50) means text up to 50 characters; NOT NULL means a value is required.

DML example — add a row

INSERT INTO Departments (DepartmentID, DepartmentName)
VALUES (10, 'IT');

Text values are enclosed in single quotes. The statement inserts one department record.

DQL example — read rows

SELECT DepartmentID, DepartmentName
FROM Departments;

This retrieves two columns from the Departments table without changing the stored data.

4. Primary keys and foreign keys

Primary key (PK)

A primary key uniquely identifies each row in a table. Primary-key values cannot be duplicated or NULL. In Employees, EmployeeID is the primary key: two employees cannot both have EmployeeID 101.

Foreign key (FK)

A foreign key is a column (or set of columns) whose values refer to a key in another table. Employees.DepartmentID refers to Departments.DepartmentID. This prevents an employee from referencing a department that does not exist, provided the foreign key constraint is enforced.

Departments                             Employees
--------------------                    -------------------------
DepartmentID (PK)  10  <-------------- DepartmentID (FK)  10
DepartmentName     IT                   EmployeeID (PK)    101
                                        FirstName          Ana

One department can have many employees. This is a one-to-many relationship. A foreign key does not need to be unique: multiple employees can share DepartmentID 10.

Remember: Primary key answers “Which exact row?” Foreign key answers “Which related row in another table?”

6. DQL basics: SELECT and FROM

SELECT specifies which columns to show; FROM specifies which table to read. Each query below is independent.

Example 1 — Show all employee columns

SELECT *
FROM Employees;

* means “all columns.” Result: eight employee rows, with every column.

Example 2 — Show only first names

SELECT FirstName
FROM Employees;

Result: Ana, Ben, Cara, David, Ella, Farah, Gabe, Hana.

Example 3 — Show three selected columns

SELECT FirstName, LastName, Salary
FROM Employees;

Only the three listed columns appear. The underlying table is unchanged.

Example 4 — Show unique cities

SELECT DISTINCT City
FROM Employees;

Result: Portland, Seattle, Tacoma (one row per unique city). DISTINCT removes duplicates from the returned result.

Example 5 — Find the names of departments

SELECT DepartmentName
FROM Departments;

Result: IT, HR, Finance. Notice that FROM changes which table the query reads.

Tip: SQL keywords are usually written in uppercase for readability, but select and SELECT mean the same thing. A semicolon marks the end of a statement and is recommended.

7. WHERE: filtering rows

Filtering means keeping only rows that satisfy a condition. WHERE performs row filtering; it does not change the database.

SELECT column1, column2
FROM TableName
WHERE condition;

Example 6 — Employees in Portland

SELECT FirstName, City
FROM Employees
WHERE City = 'Portland';

Result: Ana, Cara, Ella, Gabe. Text uses single quotes; = means equality.

Example 7 — Salary greater than 70,000

SELECT FirstName, Salary
FROM Employees
WHERE Salary > 70000;

Result: Ben (72,000), Cara (80,000), Ella (95,000), Gabe (72,000), Hana (88,000).

Example 8 — Salary at least 72,000

SELECT FirstName, Salary
FROM Employees
WHERE Salary >= 72000;

Includes 72,000 itself. This returns the same five employees as Example 7 for this dataset.

Example 9 — Employees not in IT

SELECT FirstName, DepartmentID
FROM Employees
WHERE DepartmentID <> 10;

<> means “not equal.” Result: Ben, David, Ella, Gabe.

Example 10 — Two conditions using AND

SELECT FirstName, Salary, City
FROM Employees
WHERE City = 'Portland' AND Salary > 70000;

Both conditions must be true. Result: Cara, Ella, Gabe.

Example 11 — Either condition using OR

SELECT FirstName, City
FROM Employees
WHERE City = 'Seattle' OR City = 'Tacoma';

At least one condition must be true. Result: Ben, David, Farah, Hana.

Example 12 — Match a list with IN

SELECT FirstName, DepartmentID
FROM Employees
WHERE DepartmentID IN (10, 30);

Returns employees in IT (10) or Finance (30): Ana, Cara, David, Farah, Gabe, Hana.

Example 13 — Salary range using BETWEEN

SELECT FirstName, Salary
FROM Employees
WHERE Salary BETWEEN 60000 AND 80000;

BETWEEN includes both endpoints. Result: Ana, Ben, Cara, David, Gabe.

Example 14 — Names beginning with A

SELECT FirstName
FROM Employees
WHERE FirstName LIKE 'A%';

LIKE matches text patterns; % means zero or more characters. Result: Ana.

Example 15 — Job titles containing 'Manager'

SELECT FirstName, JobTitle
FROM Employees
WHERE JobTitle LIKE '%Manager%';

Result: Ella — HR Manager.

Example 16 — Hired on or after January 1, 2022

SELECT FirstName, HireDate
FROM Employees
WHERE HireDate >= '2022-01-01';

Result: Ana, David, Farah, Gabe. SQL Server recognizes this ISO-style date string in the DATE comparison.

Example 17 — Group AND/OR with parentheses

SELECT FirstName, City, Salary
FROM Employees
WHERE (City = 'Portland' OR City = 'Seattle')
  AND Salary >= 80000;

Result: Cara and Ella. Parentheses make the intended logic clear.

8. ORDER BY: sorting the result

ORDER BY controls the order in which results are displayed. ASC means ascending (small to large, A to Z); DESC means descending (large to small, Z to A). Ascending is the default.

Example 18 — Alphabetical by first name

SELECT FirstName, LastName
FROM Employees
ORDER BY FirstName ASC;

Starts Ana, Ben, Cara ...

Example 19 — Highest salary first

SELECT FirstName, Salary
FROM Employees
ORDER BY Salary DESC;

Starts Ella (95,000), Hana (88,000), Cara (80,000). Ben and Gabe tie at 72,000; their relative order is not guaranteed without another sort column.

Example 20 — Sort by city, then salary

SELECT FirstName, City, Salary
FROM Employees
ORDER BY City ASC, Salary DESC;

Cities appear alphabetically; within each city, the highest salary appears first.

Example 21 — Filter, then sort

SELECT FirstName, Salary
FROM Employees
WHERE DepartmentID = 10
ORDER BY Salary DESC;

IT employees, highest paid first: Hana (88,000), Cara (80,000), Ana (65,000), Farah (55,000).

Important: Without ORDER BY, SQL Server does not guarantee row order—even if rows appear sorted in one execution.

9. Column aliases: clearer result headings

A column alias is a temporary label for a column in the query result. Use AS to give a column a more readable heading. Aliases do not rename the actual table columns.

Example 22 — Rename result headings

SELECT FirstName AS GivenName,
       Salary AS AnnualSalary
FROM Employees;

Output column headings are GivenName and AnnualSalary.

Example 23 — Alias containing spaces

SELECT FirstName AS [First Name],
       JobTitle AS [Job Title],
       Salary AS [Annual Salary]
FROM Employees;

Square brackets let T-SQL use spaces in the displayed headings.

Example 24 — Calculated column and alias

SELECT FirstName,
       Salary,
       Salary / 12.0 AS [Approx Monthly Salary]
FROM Employees;

Calculates salary divided by 12 and gives that expression a readable name. Using 12.0 helps avoid integer-only arithmetic.

Example 25 — Put everything together

SELECT FirstName AS [Employee Name],
       City,
       Salary AS [Annual Salary]
FROM Employees
WHERE City = 'Portland' AND Salary >= 70000
ORDER BY Salary DESC;
Employee NameCityAnnual Salary
EllaPortland95000.00
CaraPortland80000.00
GabePortland72000.00

Read it in plain English: “Show the names, cities, and salaries of Portland employees earning at least 70,000, sorted from highest to lowest salary.”

The standard beginner query pattern

SELECT column1 AS [Friendly Heading], column2
FROM TableName
WHERE condition
ORDER BY column2 DESC;

Written order: SELECT → FROM → WHERE → ORDER BY. Conceptually, the table is identified first (FROM), rows are filtered (WHERE), result expressions/columns are selected (SELECT), and results are sorted (ORDER BY). The actual execution plan is determined by SQL Server's optimizer.

10. Practice questions with worked solutions

Try each task in your SQL Server query editor before opening its answer. All solutions use the HR database created above.

Practice 1: Show first and last names of every employee.
Show solution
SELECT FirstName, LastName
FROM Employees;

SELECT specifies the two columns; FROM identifies the table. Eight rows are returned.

Practice 2: Find employees who live in Seattle.
Show solution
SELECT FirstName, City
FROM Employees
WHERE City = 'Seattle';

Ben and Farah. WHERE keeps only matching rows.

Practice 3: Show employees who earn less than 65,000.
Show solution
SELECT FirstName, Salary
FROM Employees
WHERE Salary < 65000;

David (61,000) and Farah (55,000). Ana earns exactly 65,000, so she is excluded.

Practice 4: Show employee names and salaries from lowest to highest salary.
Show solution
SELECT FirstName, Salary
FROM Employees
ORDER BY Salary ASC, FirstName ASC;

Farah is first, followed by David. The second sort column provides a predictable order when salaries tie.

Practice 5: Show all IT employees (DepartmentID 10) whose salary is at least 70,000, highest salary first.
Show solution
SELECT FirstName, DepartmentID, Salary
FROM Employees
WHERE DepartmentID = 10 AND Salary >= 70000
ORDER BY Salary DESC;

Hana (88,000), Cara (80,000). Both filters must be true.

Practice 6: Display first name as “Employee” and salary as “Pay” for Portland employees.
Show solution
SELECT FirstName AS [Employee],
       Salary AS [Pay]
FROM Employees
WHERE City = 'Portland';

Four rows. AS changes the result headings only.

Practice 7: Show employees hired in 2023 or later, newest hire first.
Show solution
SELECT FirstName, HireDate
FROM Employees
WHERE HireDate >= '2023-01-01'
ORDER BY HireDate DESC;

Farah (2024-02-12), then David (2023-11-06).

Practice 8: Show the three highest-paid employees using T-SQL.
Show solution
SELECT TOP (3) FirstName, Salary
FROM Employees
ORDER BY Salary DESC;

Ella, Hana, Cara. TOP (3) is a SQL Server/T-SQL feature; ORDER BY makes “highest” meaningful.

Practice 9: Which column is the primary key of Employees? Which column is the foreign key, and what does it reference?
Show solution

EmployeeID is the primary key. DepartmentID is the foreign key and references Departments(DepartmentID). The relationship links each employee to an existing department.

Practice 10: Why is SELECT called declarative? Explain in one or two sentences.
Show solution

A SELECT query states which data the user wants. SQL Server chooses the physical steps and access methods used to produce the result, rather than requiring the programmer to write the row-by-row retrieval algorithm.
