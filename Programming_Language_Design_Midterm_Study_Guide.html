Topic 01

Language design and trade-offs

Languages provide abstractions over machine instructions. Design decisions balance readability, writability, reliability, safety, portability, implementation complexity, and performance. No single language maximizes every criterion.

Abstraction
Hides lower-level details while exposing useful operations.
Imperative vs declarative
Imperative code describes how to perform steps; declarative code describes the desired result.
Compiled vs interpreted
These describe implementation strategies, not immutable properties of a language; Python commonly uses bytecode and a virtual machine, while C is commonly ahead-of-time compiled.

Worked examples and traces

C
int total = 2 + 3;
C#
int total = 2 + 3;
Python
total = 2 + 3
Explain it yourself: Explain why a language may prioritize explicit declarations and low-level control over brevity.
Topic 02

Tokens, syntax, and formal grammars

Tokenization converts characters into tokens; parsing checks token structure against grammar rules. Syntax validity does not guarantee meaningful names, types, or behavior.

Token
A categorized unit such as identifier, keyword, literal, operator, or punctuation.
Maximal munch
A lexer generally chooses the longest token matching a rule, such as ++ rather than two + tokens.
Grammar
A formal set of productions with terminals, nonterminals, a start symbol, and production rules.
Syntax vs semantics
Syntax asks whether the structure is allowed; semantics asks whether the structure has meaning.

Worked examples and traces

Example tokens
count += 1  →  IDENT(count), OP(+=), NUMBER(1)
Example grammar
Expr → Expr + Term | Term
Term → NUMBER | ( Expr )
Explain it yourself: Classify each error: malformed token, missing closing parenthesis, or use of an undefined name.
Topic 03

Compilation pipeline, parsing and trees

A typical implementation passes through lexing, parsing, semantic analysis/name resolution/type checking, intermediate representation, optimization, and execution/code generation. Actual pipelines vary.

AST
An abstract syntax tree represents program structure while omitting many punctuation details.
Precedence
Determines which operator binds more tightly.
Associativity
Determines grouping when operators have equal precedence.
Semantic analysis
Resolves identifiers and checks contextual constraints after parsing.

Worked examples and traces

Expression
2 + 3 * 4  →  +(2, *(3, 4))
Parentheses
(2 + 3) * 4  →  *(+(2, 3), 4)
Left association
10 - 3 - 2  →  -( -(10, 3), 2 )
Explain it yourself: Draw the AST for x = (2 + 3) * 4 and label the root and child operations.
Topic 04

Variables, binding and lifetime

A name can be bound to a value, object, storage location, type, or declaration depending on the language model. Declaration, initialization, assignment, mutation, and rebinding are distinct concepts.

Declaration
Introduces a name, often with a type.
Initialization
Provides an initial value.
Assignment/rebinding
Changes a variable’s stored value or the object to which a name refers.
Lifetime
The time during execution when an entity exists; not the same as textual scope.
Static/dynamic binding
Binding decisions can be made before execution or during execution; specify what is being bound.

Worked examples and traces

C
int x;
x = 7;
C#
var x = 7; // inferred static type int
Python
x = [1, 2]
y = x
x = [3]  # y still refers to the original list
Explain it yourself: Distinguish the name x, its current binding, and the lifetime of an object previously referenced by x.
Topic 05

Conditionals, entry points and top-level code

Conditionals select a branch using a condition. C and C# commonly use braces for blocks; Python uses indentation. Entry-point conventions differ across implementations.

C
Execution ordinarily begins at main.
C#
A program may use an explicit Main method or top-level statements.
Python
A script executes top-level statements; the __name__ guard prevents certain code from running on import.
Topic 06

Type systems and type inference

A type system classifies expressions and constrains operations. Static vs dynamic typing describes when types are checked; strong vs weak is informal and context-dependent. Type inference does not necessarily mean dynamic typing.

Static typing
Many type constraints are checked before execution (e.g., C#, C).
Dynamic typing
Operations are type-checked at runtime (e.g., Python).
Type inference
The compiler infers a type from context; C# var still has a fixed static type.
Soundness
Informally, well-typed programs avoid certain specified classes of runtime type errors; guarantees depend on the language and assumptions.
Null safety
Language mechanisms that limit unintended null use, often with explicit nullable types and flow checks.

Worked examples and traces

C#
var count = 5; // int, not dynamic
// count = "five"; // compile-time error
Python
count = 5
count = "five"  # valid rebinding
Explain it yourself: Why does C# var not make C# dynamically typed?
Topic 07

Stack, heap, values and references

Stack frames commonly hold call-local bookkeeping and some local data; heaps support dynamically allocated objects. Exact placement depends on language, runtime, optimization, and escape behavior. Value vs reference semantics should not be equated mechanically with stack vs heap.

Value semantics
Copies can represent independent values.
Reference semantics
Multiple references can point to one mutable object.
Garbage collection
Runtime identifies unreachable managed objects and may reclaim their memory.
Dynamic arrays
Resizable arrays may allocate a larger backing store and copy existing elements as capacity grows.

Worked examples and traces

C#
int a = 4; int b = a; b = 9; // a remains 4
Python
a = [1]; b = a; b.append(2)
print(a)  # [1, 2]
Explain it yourself: Explain why two references can observe the same mutation, while copying an integer does not produce shared mutable state.
Topic 08

Mutability, immutability and aliases

Mutating an object changes its state; rebinding a name changes which object the name refers to. Python lists are mutable and integers/strings immutable. C# string is immutable; StringBuilder is mutable. C const restrictions require careful reading of what is const.

Alias
Another name/reference for the same object.
Immutable object
Its observable state cannot be changed after creation.
Rebinding
A variable points to a different object; the previous object need not change.
String concatenation
Repeated concatenation may allocate many intermediate strings; builders or joins can be more efficient.

Worked examples and traces

Python
a = [1]
b = a
b.append(2)  # a is now [1, 2]
b = [9]       # a remains [1, 2]
C#
string s = "a"; s += "b"; // new string value
var sb = new System.Text.StringBuilder("a");
sb.Append("b"); // mutates builder
Explain it yourself: Contrast mutation of a list with rebinding a name to a different list.
Topic 09

Boxing, unboxing, and generics

In C#, boxing converts a value type to an object/interface representation, typically allocating a boxed object; unboxing checks and extracts the original value type. C has no equivalent built-in automatic boxing mechanism. Python integers are already objects in its usual runtime model.

Boxing
Converts a value-type value into a boxed object representation.
Unboxing
Extracts the value type from a boxed value with a compatible cast.
Generic collections
List<int> can store integers without boxing each element as object.
Performance
Repeated boxing can add allocations and garbage-collection pressure.

Worked examples and traces

C#
int n = 42;
object boxed = n;    // boxing
int restored = (int)boxed; // unboxing
C# caution
object boxed = 42;
// long x = (long)boxed; // InvalidCastException
Explain it yourself: Why is (long)boxed invalid when boxed contains an int, even though int can normally convert to long?
Topic 10

SQL Server and declarative programming

SQL describes desired result sets; SQL Server parses, binds, optimizes and executes the request. SQL Server is the database engine; SQL is the language; T-SQL is Microsoft’s dialect; SSMS is a management/query tool.

DDL
Schema definitions such as CREATE TABLE.
DML
Data changes such as INSERT, UPDATE, DELETE.
Querying
SELECT projects columns; WHERE filters; ORDER BY sorts.
Keys
A primary key identifies rows; a foreign key references a candidate/primary key in another table.
Optimization
The database engine chooses a physical execution strategy for a logically equivalent query.

Worked examples and traces

T-SQL
SELECT FirstName, Salary
FROM Employees
WHERE DepartmentID IN (10, 30)
ORDER BY Salary DESC;
T-SQL INSERT
INSERT INTO Departments (DepartmentID, DepartmentName)
VALUES (40, 'Research');
Explain it yourself: Describe the difference between specifying which rows to return and specifying the algorithm for iterating through those rows.
Topic 11

SQL filters, wildcards and query reasoning

LIKE performs pattern matching; SQL Server supports %, _, [abc], and [^abc] patterns. Quoted patterns are strings, and predicates may be combined using AND/OR. Query results are not guaranteed to be sorted without ORDER BY.

LIKE %
Matches zero or more characters.
LIKE _
Matches exactly one character.
LIKE [AB]
Matches one character from the bracketed set in SQL Server.
LIKE [^AB]
Matches one character not in the set in SQL Server.
IN
Tests membership in a set of specified values.

Worked examples and traces

T-SQL
SELECT FirstName
FROM Employees
WHERE FirstName LIKE 'A%';
T-SQL
SELECT FirstName
FROM Employees
WHERE FirstName LIKE '_a%'
ORDER BY FirstName;
Explain it yourself: Explain the difference between LIKE 'A%', LIKE 'A_', and LIKE '%A%'.

Practice questions with explanations

Try each question before opening its answer. These are conceptual practice questions, not copies of the midterm.

1. What is a key reason for creating high-level programming languages?

Answer and reasoning: To express computations through abstractions rather than manually writing machine instructions.

2. Is a syntactically valid program necessarily semantically valid?

Answer and reasoning: No. For example, an undefined identifier may parse successfully but fail name resolution.

3. What are the tokens in total += 2?

Answer and reasoning: Identifier total, operator +=, numeric literal 2.

4. What is the root of the AST for 2 + 3 * 4?

Answer and reasoning: Addition; multiplication is the right child because * has higher precedence.

5. What changes when writing (2 + 3) * 4?

Answer and reasoning: The grouping and AST: multiplication becomes the root.

6. In Python, does assignment to a local name mutate a previously referenced list?

Answer and reasoning: Not by itself. Rebinding the name leaves the original list unchanged.

7. Why is C# var statically typed?

Answer and reasoning: Its type is inferred at compile time and remains fixed for that variable.

8. Can a reference-type object always be assumed to live on the heap?

Answer and reasoning: No; implementation and optimization details matter, and reference/value semantics are not a universal memory-location rule.

9. What does boxing do in C#?

Answer and reasoning: It wraps/copies a value-type value into a boxed object representation.

10. Why can unboxing object boxed = 42 as long fail?

Answer and reasoning: The boxed runtime value is an int; unboxing requires the matching underlying value type.

11. What is the main difference between string and StringBuilder in C#?

Answer and reasoning: string is immutable; StringBuilder is mutable.

12. What happens when two Python names reference the same list and one appends?

Answer and reasoning: Both names observe the modified shared list.

13. What is the difference between SQL and SQL Server?

Answer and reasoning: SQL is a query language; SQL Server is a DBMS that implements and executes it.

14. What does WHERE do?

Answer and reasoning: Filters rows according to a predicate.

15. What does LIKE 'A_%' match?

Answer and reasoning: Strings beginning with A and containing at least one additional character.

16. Why include ORDER BY?

Answer and reasoning: Without it, the order of returned SQL rows is not guaranteed.

17. What is a foreign key?

Answer and reasoning: A column or set of columns constrained to reference a key in another or the same table.

18. Does Python require an explicit main function?

Answer and reasoning: No. Top-level module statements execute when a module is run; a __name__ guard is a convention for run-only code.

19. Why might repeated immutable string concatenation be costly?

Answer and reasoning: It can create repeated intermediate strings and copying work.

20. What distinguishes declarative SQL from an imperative loop?

Answer and reasoning: SQL specifies the requested result; an imperative loop specifies steps for obtaining it.
